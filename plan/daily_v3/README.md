# daily_v3 —— 補齊 39 格

## 為什麼有 v3

v2 的 100 格生了 138 張，使用者留 64 張。她的三個判讀：

1. **動作／構圖模組化**（`review/soul_pilot/FINDING_pose_module.md`）——
   100 格只用 9 種姿勢、8 種表情、4 種鏡位；同一個 slot 位置在 20 位人設之間只有 2–3 種姿勢。
2. **場景合理性**（`review/soul_pilot/FINDING_scene_plausibility.md`）——
   路人掛在僻靜場景、路人穿著沒寫、她的穿著沒綁場景。
3. **已生成過的場景就是用掉了** —— 不重新挑，v3 的場景全部是新的。

## 寫進程式的規則

| | 規則 | 依據 |
|---|---|---|
| 甲 | `people` 由場景的 `publicness` 推導，不再逐格手掛；僻靜場景一律 solo | 使用者：僻靜場景不該有路人 |
| 乙 | 路人穿什麼由場景的 `crowd` 決定；她穿什麼由場景的 `dress` 限制 | 使用者：田地出現西裝男、度假洋裝下田 |
| 丙 | 牆面用正面描述（`rulefix_v1` 2/2 驗證通過），不用否定句 | `VERDICT_rulefix_v1.md` |
| 丁 | **判準是「她比背景亮」，不是白天或晚上。** 夜間四種＋白天七種，日／夜各半；K9 / K14 / K7 / K3 / K1 / K11 全禁 | 使用者選片的留存率：K9（天空比她亮）0%，但 K15（日光＋室內壓暗）100%、K4（陰天正面光）100% —— 失敗的是背景比她亮，不是白天 |
| 戊 | 砍掉對鏡自拍（20%，且手機物理錯）與膝上 1.5m（26%）；新增低角度仰拍、背影回眸、坐姿俯拍 | 使用者選片的鏡位留存率 |
| 己 | 姿勢、服裝、場景在整批 39 格內都不得重複；場景不得與 v2 重疊 | 使用者：動作太單一、場景已用掉 |
| 庚 | 肢體預算在指派階段就擋（自拍只有一隻手可用，姿勢＋手持小物成本不得超過） | v2 第三隻手的舊缺陷 |

## 使用者調過的兩項

- **日／夜各半**（使用者：「為什麼夜間的占比這麼大？我覺得要各半吧」）。
  原本 30/39 是夜間 —— 那是我把「她比背景亮」這條推論直接做成「晚上」，收得太窄。
  補了五種白天光，每一種都靠場景結構把背景壓暗，而不是靠天黑：
  騎樓／拱廊光、樹縫透光、隧道口光、室內窗光、陰天但背景是暗色石材或樹蔭。
  日／夜配額改成驅動「選哪個場景」，不是選定場景後才挑光 —— 否則抽到只有夜景光的場景就補不回來。
- **有路人 6/39，使用者表示不用那麼多沒關係**，維持現狀。
