# 決策：身材規格落差處理方式 —— 採 (B)（使用者裁決，2026-09-07）

## 背景

cheryl-soh 的 Soul 驗證圖 V1/V4 顯示胸圍明顯低於 `profile.json` 寫的
`bust_cm: 89 / cup_size: D`。

追查來源：把訓練集與驗證圖的上半身並排比對後確認，**訓練集本身就已經低於
那個數字**（TRAIN03 合身背心呈現中等，TRAIN05 黑色細肩帶偏纖細）。
所以這不是 Soul 學壞，Soul 是忠實學了訓練集；落差在 `profile.json` 的數字
與訓練集之間。

## 三個選項與使用者的選擇

| | 做法 | 成本 |
|---|---|---|
| A | 接受目前呈現，把 profile 數字改成符合實際 | 0 |
| **B** | **維持 profile 數字，之後靠 prompt 補** | **0** |
| C | 訓練集重做 | 極高（19 位全部重來） |

**使用者選擇 (B)。**

## (B) 的操作含意

1. `profile.json` 的 `bust_cm: 89`、`cup_size: D` **維持不動**，不改成符合現況。
2. Soul 訓練集**不重做**。19 位既有的 5 張訓練集全部保留。
3. 身材落差**在出圖階段用 prompt 補**。

## (B) 帶來的一個既有規則衝突，必須注意

`ACCEPTANCE_LOCKED.md` §二 明文禁止在**驗證圖**的 prompt 裡重述三圍數字，
理由是「若 prompt 重述五官或掛 element，測到的是 prompt 補出來的，不是 Soul 學到的」。

這條規則**只適用於驗證圖**，目的是讓測驗乾淨。

(B) 說的「靠 prompt 補」是指**正式產出的內容圖**，那不是測驗，可以也應該寫。
兩者不衝突，但不可混用：

- **驗證圖** → 永遠不寫三圍。否則測驗失效。
- **正式內容圖** → 可以寫身材描述來把胸圍補到設定值。

## 待辦（本決策衍生）

- 在 `KOL_TRAINING_SOP.md` 或 `SEXY_SCENE_LIBRARY.md` 增訂「正式出圖時的身材
  補正寫法」，並實測一次確認 prompt 真的補得動（`SEXY_SCENE_LIBRARY.md` 已記載
  「覆蓋度無法用 prompt 可靠控制」，身材是否可控**尚未驗證**，不可預設有效）。
- 若實測證明 prompt 補不動身材，需回頭把此決策重新提交使用者。
