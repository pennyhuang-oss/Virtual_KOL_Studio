## 2. 社群帳號策略：三個方案

### 方案 1｜單一選秀主帳號輪替發布　★ 客戶方傾向

開 **1 個**選秀官方帳號（例如 `@897.girls`），20 位參賽者輪替發布。

| | |
|---|---|
| **優點** | 流量集中，演算法養成最快；營運工時最低（1 個帳號 vs 20 個）；素材需求最低；冷啟動只需做一次 |
| **缺點** | 個體辨識度低，粉絲難以「追」單一人設；打投需要使用者記得住某一位，這點被削弱；成團後 3 人若要獨立經營，等於從零開始 |
| **營運工時估計** | 1 人可兼任（每日 1–2 則） |
| **適合** | 客戶想用最低成本驗證這個玩法 |

### 方案 2｜每位人設各開一個帳號（20 個）

| | |
|---|---|
| **優點** | 真實感最高，最接近真實選秀；粉絲可以追單一人設；成團後可直接延續 |
| **缺點** | 營運工時 ×20；20 次冷啟動，多數帳號會長不起來；流量嚴重分散；素材需求 ×20（每個帳號都要餵內容才不會像殭屍帳號） |
| **營運工時估計** | 至少 3–4 人專職 |
| **適合** | 客戶有大型營運團隊且願意長期投資 |

### 方案 3｜主帳號 ＋ 論壇個人專頁 ＋ 成團後才分帳　★ 我們的建議

這是我們最推薦的做法，理由是它**把個體辨識度做在客戶自己的資產上**。

```
選秀期                          成團後
┌─────────────────────┐        ┌─────────────────────┐
│ 社群：1 個選秀主帳號 │        │ 社群：1 個團體官方帳號│
│  20 位輪替發布       │  ───►  │  ＋ 3 個成員帳號     │
├─────────────────────┤        │   （小 8／小 9／小 7）│
│ 897 論壇：           │        ├─────────────────────┤
│  20 個「參賽者專頁」 │        │ 897 論壇：           │
│  每位一個獨立主題帖  │        │  團體專版            │
│  ＝個體辨識度的載體  │        │  ＋ 12 位落選者轉常駐 │
└─────────────────────┘        └─────────────────────┘
```

**為什麼這樣更好：**

1. **客戶是論壇經營者，流量該回到論壇。** 社群平台只是漏斗頂端，把粉絲導到 IG 追蹤某一位，
   對客戶沒有直接價值；導到 897 論壇的參賽者專頁追蹤，帶動的是簽到、積分、發文與留存——
   那才是客戶的營運 KPI。
2. **個體辨識度不需要靠開 20 個社群帳號換。** 論壇的 Portal API（`Forum/X`／`Forum/Y`／`Forum/P`）
   支援自動發文與回文，所以 20 個參賽者專頁可以由 AI Agent 自動維護：每日更新她的票數、
   新素材、留言互動。**營運工時接近零，但每位人設都有自己的「家」。**
3. **成團後才開個人帳號，是資源投在對的地方。** 選秀期不知道誰會紅，開 20 個是亂槍打鳥；
   成團的 3 位是使用者票選出來的，已經驗證有粉絲，這時候開帳號的成功率最高。
4. **落選的 12 位不是浪費。** 轉為論壇常駐內容或第二季預備軍——這 12 位的人設與素材都還在。

| | |
|---|---|
| **營運工時估計** | 選秀期 1 人（社群）＋ AI Agent（論壇專頁自動化）；成團後 2 人 |
| **需要客戶做的技術工作** | 參賽者專頁的自動發文腳本（可掛在既有 9 支 AI Agent 矩陣下） |
| **適合** | 客戶想讓這個企劃同時服務「論壇 KPI」與「IP 養成」兩個目標 |

## 3. 打投機制：只有一種票

原案把打投拆成 A／B／C／D／E 五個「方案」，但那其實是把**元件**與**組合**混在一起講——
A／B／C 是元件，D／E 是打包方式。外部覆核也指出應改為
「**單一投票帳本 ＋ 三段內容節奏**，不要每段改變投票本質」。這一節照此收斂。

**全程一種票、一個帳本。** 賽程分幾段改變的是參賽人數與內容主題，**不改變投票方式**——
這樣客戶好講、會員好懂、爭議也最少。

| 項目 | 設計 |
|---|---|
| 票怎麼來 | 每日簽到 3 票（連續 7 天 +2／30 天 +5）＋ 積分兌票（100 積分 = 1 票，每日上限 10 票）＋ 每日首篇發文或回文 +1 票 |
| 票的性質 | **活動票**：當日有效、不累積、不可轉讓、不可退回積分。不直接拿歷史積分當票，避免老帳號的積分存量決定名次 |
| 一人幾票 | **一人一票等值**。每日可投出的票數依認證等級設上限：未認證 3／一般認證 10／實名認證 20 |
| 決選資格 | 投決選票須先完成**實名認證**——實名是「能不能投」的門檻，**不是票數倍率** |
| 結算 | 每日 00:05 由 AI Agent 自動發榜。需公布截止時間與時區、凍結期、無效票判定、同票處理與申訴程序 |
| 權限邊界 | AI Agent 只負責發榜，**無權改票或改結算**。投票服務與發文 Agent 權限分離 |

### 為什麼這樣設計

1. **為什麼一人一票等值、不用倍率**：倍率擋不住分身。辦 5 個一般認證帳號＝5 票，
   已經壓過一個實名會員的 3 票——作弊的人反而贏。真正能防的是「確認一個真人只有一個帳號」，
   倍率只是讓實名的人影響力變大，那是政策手段不是防弊手段。
2. **為什麼實名當門檻而不是倍率**：推實名率的效果一樣達到（想投決選就得實名），
   但每個人的票一樣重，結果最好對外解釋，也不會被說是用選秀結果交換個人資料。
3. **為什麼保留積分兌票但壓低上限**：897 的積分長期有「發得多、消耗少」的通膨問題，
   打投同時當積分消耗池是這個企劃對客戶最有價值的部分。每日上限把「花錢買票」的程度鎖住。
4. **為什麼票當日失效**：逼出每日回訪（DAU 是自然結果），也讓大戶無法囤票在截止前一次爆發。

**這一組設計不是選項**——是我方與外部覆核都同意的做法。

### 用到的 897 既有模組

| 897 既有模組 | 角色 |
|---|---|
| 每日簽到（連續加成） | 票的主要來源 → DAU 自然被拉動 |
| 積分經濟 | 票的兌換貨幣 → 打投同時是積分消耗池 |
| 等級認證（一般／實名） | 每日票上限與決選資格 |
| Portal API（全程可自動化） | 排行榜自動發布、賽果自動結算 |
| AI Agent 矩陣（9 支） | 自動發文、自動報表（**無改票權限**） |
| 輪盤抽獎、競猜、禮物券 | 見下方「加值玩法」 |

## 3b. 加值玩法（可選，一律不影響名次）

這三項都是附加的，開或不開都不影響賽制成立。
共同前提：**不得回饋到選秀名次**，否則會產生操縱投票的動機。

| 玩法 | 做法 | 用到的模組 |
|---|---|---|
| **復活投票** | 淘汰期結束後，全體已淘汰者中由會員投票復活 1 位（R3 因此為 9 位）。**由會員主動選人，不用輪盤隨機**——隨機會讓復活變成由積分量與機率決定，那不是應援 | 積分經濟 |
| **應援輪盤** | 消耗積分抽應援物或參與獎。**只發與名次無關的獎品**，是純積分消耗池 | 輪盤抽獎、禮物券 |
| **免費預測** | 預測最終成團的 3 人組合，猜中給禮物券。**免費、每人一次、獎勵不可兌現且不可回流娛樂城**，並在決選投票開始前鎖定。移除「賠率／下注／派彩」用語 | 競猜活動、禮物券 |

> **⚠ 免費預測需外部法律意見**：即使免費，有市場價值的獎品仍涉及贈獎活動辦法、廣告揭露、
> 稅務與未成年人規範，不會因為免費就自動取得單一法律定性。
> 需由台灣執業律師就完整點數閉環出具書面意見；內部合規稽核不能替代法律意見。

## 3c. 賽程：客戶要選的（三個）

| | 精簡版 | **完整版　★ 建議** | 完整版・壓縮 |
|---|---|---|---|
| 總賽程 | **3.5 週** | **7.5 週** | **6.5 週** |
| 主素材量 | 20 支 | 35 支 | 40 支 |
| 營運負荷 | 低 | 中 | 中 |
| 結構 | 不分階段，單一累計榜 | 曝光 2 週 → 淘汰 2.5 週 → 決選素材製作 1 週 → 決選 1 週 | 同左，但淘汰期就預做 10 位的決選素材，省下製作週 |
| 用不到的素材 | 0 | 0 | 5 套決選素材 |
| 優點 | 最快上線、營運最輕、素材最省 | 三段各有新聞點；素材量最省 | 賽程最短的完整賽制 |
| 缺點 | 沒有淘汰節奏，後期懸念低、容易疲乏 | 比精簡版多 4 週 | 多做 5 套用不到的素材；淘汰期製作負荷最重 |
| 適合 | 用最低成本驗證玩法 | 製作預算優先 | 上線時程優先 |

**兩個完整版的賽制完全相同**——打投規則、淘汰節奏、成團機制、客戶端營運工作都一樣，
差別只在決選素材什麼時候做。客戶要決定的是：**多花約 5 支影片的製作成本換 1 週賽程，值不值得。**

> **為什麼不能只把製作週砍掉就變 6.5 週**：那一週的存在是因為「還不知道誰進前 5，
> 就做不出他們的決選素材」。壓縮版是真的解開這個約束（預做 10 套），
> 而不是把約束忽略掉——所以它的代價是素材量，不是風險。

## 3d. 其他評估過但不建議的做法

列出來是為了讓客戶知道這些都想過了，以及為什麼不採用。

| 做法 | 為什麼不採用 |
|---|---|
| 純票數、不做身分驗證 | 擋不住分身——一個人開 10 個帳號就有 10 倍影響力。結果一旦被質疑刷票，沒有任何說法可以自證 |
| 票數 ＋ 客戶評審（70/30） | 使用者投了票卻不是最終決定者，會被質疑黑箱，選秀的公信力受損 |
| 實名認證的票算 3 倍 | 倍率擋不住分身（見上方說明），且決選可能被少數實名會員支配，也可能被解讀為用選秀結果換個資 |
| 用歷史積分直接當票 | 積分存量大的老會員會直接決定名次，一般會員迅速認定結果與自己無關 |
| 輪盤隨機決定復活者 | 復活變成由積分量與機率決定，不是應援，直接損害公信力 |
| 有下注性質的預測（投積分、給賠率、派彩） | 積分可轉入娛樂城，這個組合具備賭博風險（《刑法》第 266 條）。第一季不建議 |
| 每階段換一種投票方式 | 提高教學、客服與爭議成本，會員難以判斷一票的相對價值。改為全程同一種票 |

## 4. 最後 3 人怎麼選出來

**決選票數前 3 名成團。投決選票須先完成實名認證，一人一票等值。**
這已包含在 §3 的單一機制裡，不是另一個要選的項目。

四種曾評估過的成團機制與不採用的理由見 §3d；其中「實名 ×3 倍率」的問題最值得一提，
因為它看起來最像防弊設計，實際上不是：

| | 票數 |
|---|---|
| 作弊者辦 5 個「一般認證」帳號 | 5 × 1 ＝ **5 票** |
| 誠實的實名會員 | 1 × 3 ＝ **3 票** |

**作弊的人贏。** 倍率並沒有防到分身。
反過來看：如果「一般認證」本來就能保證一人只有一個帳號，那分身根本辦不到，
×3 也就沒有防弊的必要。倍率實際上只做了一件事——讓實名的人影響力變大。

**配套**：提前 2 週開放免費、低摩擦的實名認證，並用「完成認證即送票」化解未認證會員的相對剝奪感。

## 4b. 身形規格的使用範圍（分層原則）

本提案與配套網站上的身高、三圍、罩杯是**選角判斷依據**，屬於製作端資料，
用途是讓客戶在挑人時看得到條件差異。

**但 897 論壇的對外投票頁不採用這組欄位。** 對外頁以才藝證據與性格鉤子為主，
不顯示三圍與罩杯。兩個理由：

1. **避免活動被理解成身材排行而不是才藝選秀**——那會影響平台觸及、廣告品牌安全，也偏離選秀的訴求。
2. **5 位真人參賽者與 AI 人設同場競爭。** 若對外頁公布身材數據，真人會被放在同一張排行榜上比較，
   這是實質的騷擾與比較壓力來源。**真人參賽者頁一律不放身材數據。**

### 續營運與停損判準（建議開賽前談定）

選秀是一次性事件，成團之後才是長期營運。但成效不如預期是完全可能的：
若論壇實際參與人數有限，客戶未必要繼續投入資源經營這個女團。

**這件事建議在開賽前先講清楚**，而不是等賽程跑完才決定，因為它會回頭影響三個決定：
代號要不要雙品牌、成團後 90 天內容庫要不要現在就做、落選 12 位的後續安排。

建議先定義量化判準（合格投票人數、首投→次週留存、論壇新增與舊會員回流、實名轉換率、無效票率），
並約定兩條路徑：

- **達標** → 啟動成團後 90 天營運（此時雙品牌與內容庫才有投資價值）
- **未達標** → 走收斂路徑：公布成團結果作為完整結局，素材轉為論壇常駐內容，不再擴大投入
