## 0. 誰做什麼（提案的商務基礎）

這是本專案最需要先講清楚的一件事，因為它決定報價範圍與雙方的交付責任。

| | **兌心科技（我們）** | **客戶營運團隊** |
|---|---|---|
| 虛擬 KOL 人設 | **提供**：人設設定、形象規格、才藝設定、臉部一致性 | 使用 |
| AIGC 素材 | **產出**：才藝表演影片（跳舞／唱歌／各類才藝）、日常圖片素材 | 排程與發布 |
| 社群帳號 | 不負責 | **開設與營運**：發文、互動、留言回覆、粉絲經營 |
| 897 論壇打投系統 | 不負責（可提供機制設計建議＝本文件） | **建置與營運**：打投模組、賽程、結算、風控 |
| 賽事主持與公告 | 可產出主持素材（例如 Emma 的播報影片） | **執行**：公告、賽果發布、爭議處理 |

賽程長度、每輪幾個人、多久發一次，直接決定我們要產幾支影片。這一節談不清楚，報價就估不準。

## 2. 社群帳號策略：三個方案

### 方案 1｜單一選秀主帳號輪替發布　★ 客戶方傾向

開 **1 個**選秀官方帳號（例如 `@897.girls`），20 位參賽者輪替發布。

| | |
|---|---|
| **優點** | 流量集中，演算法養成最快；營運工時最低（1 個帳號 vs 20 個）；素材需求最低；冷啟動只需做一次 |
| **缺點** | 個體辨識度低，粉絲難以「追」單一人設；打投需要使用者記得住某一位，這點被削弱；成團後 3 人若要獨立經營，等於從零開始 |
| **營運工時估計** | 1 人可兼任（每日 1–2 則） |
| **適合** | 客戶想用最低成本驗證這個玩法 |

### 方案 2｜每位人設各開一個帳號（20 個）

| | |
|---|---|
| **優點** | 真實感最高，最接近真實選秀；粉絲可以追單一人設；成團後可直接延續 |
| **缺點** | 營運工時 ×20；20 次冷啟動，多數帳號會長不起來；流量嚴重分散；素材需求 ×20（每個帳號都要餵內容才不會像殭屍帳號） |
| **營運工時估計** | 至少 3–4 人專職 |
| **適合** | 客戶有大型營運團隊且願意長期投資 |

### 方案 3｜主帳號 ＋ 論壇個人專頁 ＋ 成團後才分帳　★ 我們的建議

這是我們最推薦的做法，理由是它**把個體辨識度做在客戶自己的資產上**。

```
選秀期                          成團後
┌─────────────────────┐        ┌─────────────────────┐
│ 社群：1 個選秀主帳號 │        │ 社群：1 個團體官方帳號│
│  20 位輪替發布       │  ───►  │  ＋ 3 個成員帳號     │
├─────────────────────┤        │   （小 8／小 9／小 7）│
│ 897 論壇：           │        ├─────────────────────┤
│  20 個「參賽者專頁」 │        │ 897 論壇：           │
│  每位一個獨立主題帖  │        │  團體專版            │
│  ＝個體辨識度的載體  │        │  ＋ 12 位落選者轉常駐 │
└─────────────────────┘        └─────────────────────┘
```

**為什麼這樣更好：**

1. **客戶是論壇經營者，流量該回到論壇。** 社群平台只是漏斗頂端，把粉絲導到 IG 追蹤某一位，
   對客戶沒有直接價值；導到 897 論壇的參賽者專頁追蹤，帶動的是簽到、積分、發文與留存——
   那才是客戶的營運 KPI。
2. **個體辨識度不需要靠開 20 個社群帳號換。** 論壇的 Portal API（`Forum/X`／`Forum/Y`／`Forum/P`）
   支援自動發文與回文，所以 20 個參賽者專頁可以由 AI Agent 自動維護：每日更新她的票數、
   新素材、留言互動。**營運工時接近零，但每位人設都有自己的「家」。**
3. **成團後才開個人帳號，是資源投在對的地方。** 選秀期不知道誰會紅，開 20 個是亂槍打鳥；
   成團的 3 位是使用者票選出來的，已經驗證有粉絲，這時候開帳號的成功率最高。
4. **落選的 12 位不是浪費。** 轉為論壇常駐內容或第二季預備軍——這 12 位的人設與素材都還在。

| | |
|---|---|
| **營運工時估計** | 選秀期 1 人（社群）＋ AI Agent（論壇專頁自動化）；成團後 2 人 |
| **需要客戶做的技術工作** | 參賽者專頁的自動發文腳本（可掛在既有 9 支 AI Agent 矩陣下） |
| **適合** | 客戶想讓這個企劃同時服務「論壇 KPI」與「IP 養成」兩個目標 |

## 3. 打投機制：四個方案（結合 897 論壇既有模組）

897 論壇本身已經有的模組，是設計打投時最該利用的資產。以下每個方案都標明它用到哪些：

| 897 既有模組 | 在打投設計中的角色 |
|---|---|
| **每日簽到**（連續加成） | 票的主要來源 → 選秀期間 DAU 自然被拉動 |
| **積分經濟**（發文／回文／簽到／活動） | 票的兌換貨幣 → 打投同時是積分消耗池 |
| **輪盤抽獎**（積分消耗型，設計目的是抑制積分通膨） | 復活賽／應援加成道具 |
| **競猜活動**（賠率、賽事預測） | 預測誰成團的附加玩法 |
| **禮物券兌換** | 投票行為的獎勵回饋 |
| **等級認證**（一般等級＝活躍度、認證等級＝實名） | **票權重與防分身** → 同時推動實名率 |
| **Portal API**（會員／發文全程可自動化） | 排行榜自動發布、賽果自動結算 |
| **AI Agent 矩陣（9 支）** | 自動發文、自動回覆、自動報表 |

---

### 方案 A｜積分應援榜（最快上線、營運最輕）

**票怎麼來**

| 來源 | 數量 | 掛在哪個模組 |
|---|---|---|
| 每日簽到 | 每日 3 票 | 既有簽到 |
| 連續簽到加成 | 連 7 天 +2／連 30 天 +5 | 既有簽到加成 |
| 積分兌換 | 100 積分 = 1 票，每日上限 10 票 | 既有積分 |
| 發文／回文 | 每日首篇 +1 票 | 既有積分行為 |

**規則**
- 票**當日有效、不累積、不可轉讓** → 逼出每日回訪，也讓大戶無法囤票一次爆發
- 每日票數上限依認證等級：**未認證 3 票／一般認證 10 票／實名認證 20 票**
- 排行榜由 AI Agent 每日 00:05 透過 Portal API 自動發文
- 全程單一累計榜，賽程結束取前 3

**優點**：最簡單、最快上線、營運負荷最低、DAU 拉動最直接
**缺點**：積分多的大戶影響力大；沒有淘汰節奏，後期懸念低、容易疲乏
**營運負荷**：低（R9 設定活動，其餘 AI Agent 自動化）
**建議賽程**：3–4 週

---

### 方案 B｜賽季淘汰制（懸念最高、內容節奏最好）

分 4 輪，**每輪票數歸零**，這是懸念的來源。

| 輪次 | 主題 | 人數 | 期間 | 我方素材需求 |
|---|---|---|---|---|
| R1 | 自我介紹 | 20 → 12 | 2 週 | 20 支自我介紹影片 |
| R2 | 才藝初演 | 12 → 8 | 2 週 | 12 支才藝影片 |
| R3 | 才藝決演 | 8 → 5 | 1.5 週 | 8 支進階才藝影片 |
| R4 | 成團決選 | 5 → 3 | 1 週 | 5 支決選影片 ＋ 團體合演素材 |
| | | | **6.5 週** | **合計 45 支** |

**復活賽（用既有輪盤模組）**
R2 結束後，被淘汰的 8 位進入「復活輪盤」。會員消耗 **500 積分抽一次**，
抽中者該位 +1 復活票，票數最高的 1 位復活。
→ 這一段同時達成三件事：消耗積分（抑制通膨）、給落選者第二次曝光、製造一個新聞點。

**優點**：懸念與新聞點最多；人數遞減讓素材總量可控；每輪都是一次重新行銷的機會
**缺點**：賽程最長；營運工時最高（每輪換主題頁、發淘汰公告、處理爭議）
**營運負荷**：高（R9 活動營運 ＋ R10 內容版主需投入）
**建議賽程**：6.5 週

---

### 方案 C｜預測競猜雙軌（最貼合 897 用戶既有行為）

**兩條軌道並行，但只有一條決定結果。**

| 軌道 | 作用 | 用到的模組 |
|---|---|---|
| **應援軌** | 決定實際名次，規則同方案 A | 簽到、積分、等級認證 |
| **預測軌** | 附加玩法，**不影響名次** | **既有競猜模組**、禮物券 |

**預測軌怎麼玩**
- 每輪開一次「誰會成團」的預測盤，會員預測最終 3 人組合
- 賠率由參與分布動態計算（競猜模組現成能力）
- 猜中依難度給禮物券／積分回饋
- **關鍵設計：預測結果不回饋到選秀名次**——否則會產生操縱投票的動機

**優點**：最大化 897 核心模組的價值；897 的使用者本來就在做競猜，這是他們最熟悉的行為，
參與門檻最低、留存效果最強
**缺點**：需要風控與合規介入；玩法較複雜，需要教學成本

**⚠ 一個需要客戶法務判斷的設計點（提供資訊，決定權在客戶）**
論壇的積分可轉入外部娛樂城。因此「投入積分預測 → 猜中獲得積分回饋」在**金流性質上具備下注特徵**。
若客戶希望明確與博弈玩法區隔，有兩個現成的調整方向：
- **零成本預測**：預測免費，猜中才給獎勵 → 性質為行銷抽獎
- **獎勵不可回流**：預測獎勵發成禮物券／實體獎品，不發可轉娛樂城的積分

這一點我們無法代替客戶判斷，但**建議在賽制定案前先讓客戶的 R5 合規／反洗錢稽核過一次**，
因為賽制上線後再改，會影響已投票的會員權益。

**營運負荷**：中（＋R3 風控、R5 合規）
**建議賽程**：搭配 A 或 B 使用

### 方案 D｜混合三階段制　★ 我們的建議

把 A 的低成本、B 的懸念、C 的參與度各取一段，放在最適合的階段。

```
前置期 1 週          階段一 2 週        階段二 2.5 週       階段三 1 週
首波素材製作      →  曝光期（20 位）  →  淘汰期（10 位）  →  決選期（5 位）→ 成團
                     純累計應援          票數歸零            票權加權
                     ＝方案 A            ＋復活輪盤          ＋免費預測軌
                                         ＝方案 B            ＝方案 C
```

| 階段 | 期間 | 人數 | 打投規則 | 啟動的 897 模組 | 我方素材 |
|---|---|---|---|---|---|
| **前置期** | 1 週 | — | 未開放 | 預熱貼文、參賽者專頁上線 | 20 支自我介紹影片 |
| **階段一 曝光期** | 2 週 | 20 | 每日簽到票累計 | 簽到、積分、Portal API | 輪替發布既有素材 |
| **階段二 淘汰期** | 2.5 週 | 10 | 票數歸零重計 ＋ 復活輪盤 | ＋輪盤、禮物券 | 10 支才藝影片 |
| **階段三 決選期** | 1 週 | 5 | 票權加權（實名 ×3） | ＋競猜（免費預測） | 5 支決選 ＋ 團體合演 |
| **合計** | **6.5 週** | | | | **約 35 支影片** |

**為什麼是這個組合：**

1. **素材產能對得上。** 15 位建模已全部完成，曝光期可直接輪替既有 21 支素材並同步產新素材；
   才藝影片的需求落在人數已減半的淘汰期。**總量從方案 B 的 45 支降到 35 支。**
2. **賽程 6.5 週落在注意力週期內。** 選秀類企劃超過 8 週會明顯疲乏。
3. **營運資源投在後段。** 曝光期幾乎全自動，把 R9／R10 的人力集中在淘汰期與決選期。
4. **積分消耗池分三段釋放。** 每階段啟動不同模組（積分兌票 → 輪盤 → 預測），
   避免單一玩法疲乏，也讓積分回收曲線平順。
5. **實名率是附帶收穫。** 決選期的票權加權讓實名認證有實質好處，這對客戶的長期合規有利。

## 4. 最後 3 人怎麼選出來：四個方案

**這一節要解決的問題只有一個：怎麼防止一個人開很多帳號來刷票。**

| 方案 | 機制 | 白話的取捨 |
|---|---|---|
| **甲** 純票數 | 決選票前 3 名成團，不做身分驗證 | 最單純，但擋不住分身——一個人開 10 個帳號就有 10 倍影響力，結果被質疑時沒有任何說法可以自證 |
| **乙** 票數 ＋ 評審 | 票數 70% ＋ 客戶評審 30% | 可以調整結果（例如確保才藝互補），但使用者投了票卻不是最終決定者，會被質疑黑箱 |
| **丙** 實名票算 3 倍 | 實名 ×3／一般認證 ×1／未認證不可投 | 推實名率最有力，**但倍率其實擋不住分身**（見下方） |
| **丁** 一人一票等值 ＋ 實名當資格　★ 建議 | 決選一人一票、票票等值；但要投決選票必須先完成實名認證 | 真正解決分身，推實名率的效果一樣達到，公信力最乾淨 |

### 為什麼「實名 ×3」擋不住分身

這是外部覆核抓到的問題，我們認為成立。用數字看最清楚：

| | 票數 |
|---|---|
| 作弊者辦 5 個「一般認證」帳號 | 5 × 1 ＝ **5 票** |
| 誠實的實名會員 | 1 × 3 ＝ **3 票** |

**作弊的人贏。** 倍率並沒有防到分身。

反過來看：如果「一般認證」本來就能保證一人只有一個帳號，那分身根本辦不到，×3 也就沒有防弊的必要。

**結論**：倍率解決不了分身，能解決的只有「確認一個真人只有一個帳號」。
倍率實際上只做了一件事——讓實名的人影響力變大。那是推實名率的政策手段，不是防弊手段。
原案把這兩件事混在一起了。

### 方案丁的做法

- **防分身** → 一個已驗證的真人 ＝ 一個帳號 ＝ 一票（等值）
- **推實名率** → 把實名設成「能不能投決選票」的**資格門檻**，不是票數倍率

推實名率的效果一樣達到（想投決選就得實名），但每個人的票一樣重，結果最好對外解釋，
也不會被說是「用選秀結果交換個人資料」。

**給客戶的一句話**：決選一人一票、票票等值；要投決選票必須先完成實名認證。

**配套**：提前 2 週開放免費、低摩擦的實名認證，並用「完成認證即送票」化解未認證會員的相對剝奪感。
客戶需確認實名流程的體驗夠順，否則會擋掉真實的參與者。

## 4b. 第一季要不要開放「積分換投票券」

外部覆核建議第一季完全不開積分兌票。理由：積分可轉入娛樂城、因此具有實際價值，
用有價值的東西換投票權接近「花錢買票」，法律風險較高，且積分存量大的老會員會壓過一般會員。

**我方的不同意見**：這一項同時是本企劃**對客戶最有價值的部分**。
897 的積分長期有「發得多、消耗少」的通膨問題——現有的輪盤抽獎本來就是為了消耗積分而設計。
若選秀完全不碰積分，這個活動對客戶就只是多一個好玩的玩法，而不是同時處理積分回收。

**建議折中**：

| 項目 | 做法 |
|---|---|
| 積分兌票 | **保留**，但每日上限壓低（例如每日最多兌 10 票） |
| 兌出的票 | 不可轉讓、不可退回積分（單向消耗） |
| 封閉壓測 | 由 7–14 天縮短為 3–5 天 |

這樣積分消耗池還在，但「花錢買票」的程度被每日上限鎖住。
若客戶的法務傾向保守，則第一季不開兌票、只用簽到票，第二季再依實際數據評估。

## 4c. 身形規格的使用範圍（分層原則）

本提案與配套網站上的身高、三圍、罩杯是**選角判斷依據**，屬於製作端資料，
用途是讓客戶在挑人時看得到條件差異。

**但 897 論壇的對外投票頁不採用這組欄位。** 對外頁以才藝證據與性格鉤子為主，
不顯示三圍與罩杯。兩個理由：

1. **避免活動被理解成身材排行而不是才藝選秀**——那會影響平台觸及、廣告品牌安全，也偏離選秀的訴求。
2. **5 位真人參賽者與 AI 人設同場競爭。** 若對外頁公布身材數據，真人會被放在同一張排行榜上比較，
   這是實質的騷擾與比較壓力來源。**真人參賽者頁一律不放身材數據。**

### 續營運與停損判準（建議開賽前談定）

選秀是一次性事件，成團之後才是長期營運。但成效不如預期是完全可能的：
若論壇實際參與人數有限，客戶未必要繼續投入資源經營這個女團。

**這件事建議在開賽前先講清楚**，而不是等賽程跑完才決定，因為它會回頭影響三個決定：
代號要不要雙品牌、成團後 90 天內容庫要不要現在就做、落選 12 位的後續安排。

建議先定義量化判準（合格投票人數、首投→次週留存、論壇新增與舊會員回流、實名轉換率、無效票率），
並約定兩條路徑：

- **達標** → 啟動成團後 90 天營運（此時雙品牌與內容庫才有投資價值）
- **未達標** → 走收斂路徑：公布成團結果作為完整結局，素材轉為論壇常駐內容，不再擴大投入
