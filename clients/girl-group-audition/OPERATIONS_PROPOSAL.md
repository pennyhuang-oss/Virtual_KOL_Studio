## 0. 誰做什麼（提案的商務基礎）

這是本專案最需要先講清楚的一件事，因為它決定報價範圍與雙方的交付責任。

| | **兌心科技（我們）** | **客戶營運團隊** |
|---|---|---|
| 虛擬 KOL 人設 | **提供**：人設設定、形象規格、才藝設定、臉部一致性 | 使用 |
| AIGC 素材 | **產出**：才藝表演影片（跳舞／唱歌／各類才藝）、日常圖片素材 | 排程與發布 |
| 社群帳號 | 不負責 | **開設與營運**：發文、互動、留言回覆、粉絲經營 |
| 897 論壇打投系統 | 不負責（可提供機制設計建議＝本文件） | **建置與營運**：打投模組、賽程、結算、風控 |
| 賽事主持與公告 | 可產出主持素材（例如 Emma 的播報影片） | **執行**：公告、賽果發布、爭議處理 |

**我們的交付物只有兩類：人設 ＋ 素材。營運全部在客戶端。**
本文件之所以還是要寫，是因為**營運方式會反過來決定素材的規格、數量與交付節奏**——
賽程長度、每輪幾個人、多久發一次，直接決定我們要產幾支影片。這一節談不清楚，報價就估不準。

## 2. 社群帳號策略：三個方案

### 方案 1｜單一選秀主帳號輪替發布　★ 客戶方傾向

開 **1 個**選秀官方帳號（例如 `@897.girls`），20 位參賽者輪替發布。

| | |
|---|---|
| **優點** | 流量集中，演算法養成最快；營運工時最低（1 個帳號 vs 20 個）；素材需求最低；冷啟動只需做一次 |
| **缺點** | 個體辨識度低，粉絲難以「追」單一人設；打投需要使用者記得住某一位，這點被削弱；成團後 3 人若要獨立經營，等於從零開始 |
| **營運工時估計** | 1 人可兼任（每日 1–2 則） |
| **適合** | 客戶想用最低成本驗證這個玩法 |

### 方案 2｜每位人設各開一個帳號（20 個）

| | |
|---|---|
| **優點** | 真實感最高，最接近真實選秀；粉絲可以追單一人設；成團後可直接延續 |
| **缺點** | 營運工時 ×20；20 次冷啟動，多數帳號會長不起來；流量嚴重分散；素材需求 ×20（每個帳號都要餵內容才不會像殭屍帳號） |
| **營運工時估計** | 至少 3–4 人專職 |
| **適合** | 客戶有大型營運團隊且願意長期投資 |

### 方案 3｜主帳號 ＋ 論壇個人專頁 ＋ 成團後才分帳　★ 我們的建議

這是我們最推薦的做法，理由是它**把個體辨識度做在客戶自己的資產上**。

```
選秀期                          成團後
┌─────────────────────┐        ┌─────────────────────┐
│ 社群：1 個選秀主帳號 │        │ 社群：1 個團體官方帳號│
│  20 位輪替發布       │  ───►  │  ＋ 3 個成員帳號     │
├─────────────────────┤        │   （小 8／小 9／小 7）│
│ 897 論壇：           │        ├─────────────────────┤
│  20 個「參賽者專頁」 │        │ 897 論壇：           │
│  每位一個獨立主題帖  │        │  團體專版            │
│  ＝個體辨識度的載體  │        │  ＋ 12 位落選者轉常駐 │
└─────────────────────┘        └─────────────────────┘
```

**為什麼這樣更好：**

1. **客戶是論壇經營者，流量該回到論壇。** 社群平台只是漏斗頂端，把粉絲導到 IG 追蹤某一位，
   對客戶沒有直接價值；導到 897 論壇的參賽者專頁追蹤，帶動的是簽到、積分、發文與留存——
   那才是客戶的營運 KPI。
2. **個體辨識度不需要靠開 20 個社群帳號換。** 論壇的 Portal API（`Forum/X`／`Forum/Y`／`Forum/P`）
   支援自動發文與回文，所以 20 個參賽者專頁可以由 AI Agent 自動維護：每日更新她的票數、
   新素材、留言互動。**營運工時接近零，但每位人設都有自己的「家」。**
3. **成團後才開個人帳號，是資源投在對的地方。** 選秀期不知道誰會紅，開 20 個是亂槍打鳥；
   成團的 3 位是使用者票選出來的，已經驗證有粉絲，這時候開帳號的成功率最高。
4. **落選的 12 位不是浪費。** 轉為論壇常駐內容或第二季預備軍——這 12 位的人設與素材都還在。

| | |
|---|---|
| **營運工時估計** | 選秀期 1 人（社群）＋ AI Agent（論壇專頁自動化）；成團後 2 人 |
| **需要客戶做的技術工作** | 參賽者專頁的自動發文腳本（可掛在既有 9 支 AI Agent 矩陣下） |
| **適合** | 客戶想讓這個企劃同時服務「論壇 KPI」與「IP 養成」兩個目標 |

## 3. 打投機制：四個方案（結合 897 論壇既有模組）

897 論壇本身已經有的模組，是設計打投時最該利用的資產。以下每個方案都標明它用到哪些：

| 897 既有模組 | 在打投設計中的角色 |
|---|---|
| **每日簽到**（連續加成） | 票的主要來源 → 選秀期間 DAU 自然被拉動 |
| **積分經濟**（發文／回文／簽到／活動） | 票的兌換貨幣 → 打投同時是積分消耗池 |
| **輪盤抽獎**（積分消耗型，設計目的是抑制積分通膨） | 復活賽／應援加成道具 |
| **競猜活動**（賠率、賽事預測） | 預測誰成團的附加玩法 |
| **禮物券兌換** | 投票行為的獎勵回饋 |
| **等級認證**（一般等級＝活躍度、認證等級＝實名） | **票權重與防分身** → 同時推動實名率 |
| **Portal API**（會員／發文全程可自動化） | 排行榜自動發布、賽果自動結算 |
| **AI Agent 矩陣（9 支）** | 自動發文、自動回覆、自動報表 |

---

### 方案 A｜積分應援榜（最快上線、營運最輕）

**票怎麼來**

| 來源 | 數量 | 掛在哪個模組 |
|---|---|---|
| 每日簽到 | 每日 3 票 | 既有簽到 |
| 連續簽到加成 | 連 7 天 +2／連 30 天 +5 | 既有簽到加成 |
| 積分兌換 | 100 積分 = 1 票，每日上限 10 票 | 既有積分 |
| 發文／回文 | 每日首篇 +1 票 | 既有積分行為 |

**規則**
- 票**當日有效、不累積、不可轉讓** → 逼出每日回訪，也讓大戶無法囤票一次爆發
- 每日票數上限依認證等級：**未認證 3 票／一般認證 10 票／實名認證 20 票**
- 排行榜由 AI Agent 每日 00:05 透過 Portal API 自動發文
- 全程單一累計榜，賽程結束取前 3

**優點**：最簡單、最快上線、營運負荷最低、DAU 拉動最直接
**缺點**：積分多的大戶影響力大；沒有淘汰節奏，後期懸念低、容易疲乏
**營運負荷**：低（R9 設定活動，其餘 AI Agent 自動化）
**建議賽程**：3–4 週

---

### 方案 B｜賽季淘汰制（懸念最高、內容節奏最好）

分 4 輪，**每輪票數歸零**，這是懸念的來源。

| 輪次 | 主題 | 人數 | 期間 | 我方素材需求 |
|---|---|---|---|---|
| R1 | 自我介紹 | 20 → 12 | 2 週 | 20 支自我介紹影片 |
| R2 | 才藝初演 | 12 → 8 | 2 週 | 12 支才藝影片 |
| R3 | 才藝決演 | 8 → 5 | 1.5 週 | 8 支進階才藝影片 |
| R4 | 成團決選 | 5 → 3 | 1 週 | 5 支決選影片 ＋ 團體合演素材 |
| | | | **6.5 週** | **合計 45 支** |

**復活賽（用既有輪盤模組）**
R2 結束後，被淘汰的 8 位進入「復活輪盤」。會員消耗 **500 積分抽一次**，
抽中者該位 +1 復活票，票數最高的 1 位復活。
→ 這一段同時達成三件事：消耗積分（抑制通膨）、給落選者第二次曝光、製造一個新聞點。

**優點**：懸念與新聞點最多；人數遞減讓素材總量可控；每輪都是一次重新行銷的機會
**缺點**：賽程最長；營運工時最高（每輪換主題頁、發淘汰公告、處理爭議）
**營運負荷**：高（R9 活動營運 ＋ R10 內容版主需投入）
**建議賽程**：6.5 週

---

### 方案 C｜預測競猜雙軌（最貼合 897 用戶既有行為）

**兩條軌道並行，但只有一條決定結果。**

| 軌道 | 作用 | 用到的模組 |
|---|---|---|
| **應援軌** | 決定實際名次，規則同方案 A | 簽到、積分、等級認證 |
| **預測軌** | 附加玩法，**不影響名次** | **既有競猜模組**、禮物券 |

**預測軌怎麼玩**
- 每輪開一次「誰會成團」的預測盤，會員預測最終 3 人組合
- 賠率由參與分布動態計算（競猜模組現成能力）
- 猜中依難度給禮物券／積分回饋
- **關鍵設計：預測結果不回饋到選秀名次**——否則會產生操縱投票的動機

**優點**：最大化 897 核心模組的價值；897 的使用者本來就在做競猜，這是他們最熟悉的行為，
參與門檻最低、留存效果最強
**缺點**：需要風控與合規介入；玩法較複雜，需要教學成本

**⚠ 一個需要客戶法務判斷的設計點（提供資訊，決定權在客戶）**
論壇的積分可轉入外部娛樂城。因此「投入積分預測 → 猜中獲得積分回饋」在**金流性質上具備下注特徵**。
若客戶希望明確與博弈玩法區隔，有兩個現成的調整方向：
- **零成本預測**：預測免費，猜中才給獎勵 → 性質為行銷抽獎
- **獎勵不可回流**：預測獎勵發成禮物券／實體獎品，不發可轉娛樂城的積分

這一點我們無法代替客戶判斷，但**建議在賽制定案前先讓客戶的 R5 合規／反洗錢稽核過一次**，
因為賽制上線後再改，會影響已投票的會員權益。

**營運負荷**：中（＋R3 風控、R5 合規）
**建議賽程**：搭配 A 或 B 使用

### 方案 D｜混合三階段制　★ 我們的建議

把 A 的低成本、B 的懸念、C 的參與度各取一段，放在最適合的階段。

```
前置期 2 週          階段一 2 週        階段二 2.5 週       階段三 1 週
建模 ＋ 首波素材  →  曝光期（20 位）  →  淘汰期（10 位）  →  決選期（5 位）→ 成團
                     純累計應援          票數歸零            票權加權
                     ＝方案 A            ＋復活輪盤          ＋免費預測軌
                                         ＝方案 B            ＝方案 C
```

| 階段 | 期間 | 人數 | 打投規則 | 啟動的 897 模組 | 我方素材 |
|---|---|---|---|---|---|
| **前置期** | 2 週 | — | 未開放 | 預熱貼文、參賽者專頁上線 | 10 位送訓 ＋ 20 支自我介紹 |
| **階段一 曝光期** | 2 週 | 20 | 每日簽到票累計 | 簽到、積分、Portal API | 輪替發布既有素材 |
| **階段二 淘汰期** | 2.5 週 | 10 | 票數歸零重計 ＋ 復活輪盤 | ＋輪盤、禮物券 | 10 支才藝影片 |
| **階段三 決選期** | 1 週 | 5 | 票權加權（實名 ×3） | ＋競猜（免費預測） | 5 支決選 ＋ 團體合演 |
| **合計** | **7.5 週** | | | | **約 35 支影片** |

**為什麼是這個組合：**

1. **素材產能對得上。** 曝光期只需輪替發既有 21 支素材 ＋ 5 位已建模者的新素材，
   剛好給 10 位待送訓者留出建模時間；才藝影片的需求落在淘汰期，那時人數已減半。
   **總量從方案 B 的 45 支降到 35 支。**
2. **賽程 7.5 週落在注意力週期內。** 選秀類企劃超過 8 週會明顯疲乏。
3. **營運資源投在後段。** 曝光期幾乎全自動，把 R9／R10 的人力集中在淘汰期與決選期。
4. **積分消耗池分三段釋放。** 每階段啟動不同模組（積分兌票 → 輪盤 → 預測），
   避免單一玩法疲乏，也讓積分回收曲線平順。
5. **實名率是附帶收穫。** 決選期的票權加權讓實名認證有實質好處，這對客戶的長期合規有利。

## 4. 最後 3 人怎麼選出來：三個方案

| 方案 | 機制 | 優點 | 缺點 |
|---|---|---|---|
| **甲** 純票數 | 階段三票數前 3 名直接成團 | 最單純、公信力最高、爭議最少 | 完全無法調控結果 |
| **乙** 票數 ＋ 評審 | 票數 70% ＋ 客戶評審 30% | 可調控（例如確保才藝互補） | 「評審」會被質疑黑箱，選秀公信力受損 |
| **丙** 票數 ＋ 票權加權　★ 建議 | 前 5 進決選，決選票依認證等級加權（實名 ×3／一般 ×1／未認證不可投） | 仍是「使用者選出來的」＝公信力；同時防分身；推動實名率 | 未認證會員會有相對剝奪感（可用「認證即送票」化解） |

### 隊長與代號的設計建議

成團 3 人的代號已定為 **小 8／小 9／小 7**。建議直接讓代號承載名次：

| 代號 | 對應 | 理由 |
|---|---|---|
| **小 8** | 決選票數第 1 名 ＝ **隊長** | 8 在論壇語境是最強的數字，給第一名最自然 |
| **小 9** | 第 2 名 | |
| **小 7** | 第 3 名 | |

這樣公布名次與公布代號是同一個動作，**發布時只需要一則貼文就有三個話題**
（誰成團／誰是隊長／代號揭曉）。主舞、主唱、門面等定位維持不預先指派，成團後再依素材表現決定。

**盲點**：規則有三組互相不清楚的上限：票源數量、認證等級上限，以及「當日有效但全程累計榜」。未說明上限是「取得」還是「投出」、連續簽到加成是否超過上限、未使用票如何失效。現有老帳號／積分大戶、可轉移或外部取得的積分、洗回文、機器簽到、多帳號、API 重送與截止瞬間併發，都可形成刷票破口。每日 00:05 發榜不是可稽核的結算機制，也未定義時區、延遲事件、撤銷票與同票處理。

**風險等級**：高
**建議補強**：先畫出唯一的人數狀態表並重算素材：例如 20→12→8，另由全體已淘汰者中復活 1 人，則 R3 明確為 9→5。復活應讓會員**主動選人**，每個已驗證自然人限固定票數；輪盤若保留，只抽與名次無關的應援物或參與獎。各輪設 24 小時異常審核／結果暫定期，審核後再公布正式淘汰名單。

### 針對 §3 方案 C —— 預測競猜雙軌

**盲點**：目前法務判斷不夠，且「零成本＝行銷抽獎」下得太快。當積分可回流外部娛樂城或具有可交易／可兌換價值時，「投入具有價值的點數＋依不確定結果派發具有價值的回報」具有賭博風險；台灣《刑法》第 266 條也明定透過網際網路賭博財物的情形。即使預測免費，有市場價值的獎品仍涉及贈獎活動規則、廣告揭露、稅務、未成年人與公平性，不會只因免費就自動取得單一法律定性。另有產品問題：20 人選 3 人共有 1,140 種組合，動態賠率容易因流動性過低而失真；同一會員既能預測又能大量投票，仍有操縱結果的利益衝突。參考：[《刑法》第 266 條](https://mojlaw.moj.gov.tw/LawContentExtent.aspx?LawNo=266&lsid=fl001424)、[公平會網路廣告處理原則](https://law.ftc.gov.tw/law/LawContent.aspx?id=GL000222)。
**風險等級**：高
**建議補強**：第一季建議只做**免費、無下注、每人一次、獎勵不可兌現且不可回流娛樂城**的趣味預測，並移除「賠率／下注／派彩」用語；預測在決選投票開始前鎖定，或預測題改為不受本人投票直接控制的內容題。由台灣執業律師依完整點數閉環、獎品價值、參加資格、年齡與地域出具書面意見；同時公布完整活動辦法、獲獎限制、稅負、取消／更正條件。不能只由內部 R5 做「合規稽核」代替法律意見。

### 針對 §3 方案 D —— 混合三階段制

**盲點**：方案 D 繼承 A／B／C 的所有漏洞，並且缺少階段一 20→10、階段二 10→5（含復活後）如何結算的明文。前置期被算入「7.5 週注意力週期」，但實際開放投票只有 5.5 週；用這個數字支持「未超過 8 週不疲乏」沒有數據基礎。每階段換貨幣與規則會提高教學、客服與爭議成本，也讓會員難以判斷一票的相對價值。
**風險等級**：高
**建議補強**：把 D 改成「單一投票帳本＋三段內容節奏」，不要每段改變投票本質：全程皆為等值活動票，只有票數是否歸零、參賽人數及內容主題改變。預測與輪盤皆不得影響名次。先以測試帳號跑完整賽程、故障、回滾、重算、同票與封禁情境，再做 7–14 天封閉 beta；上線前公布一頁式規則與版本鎖定時間。

### 針對 §1、§3 方案 D、§5 —— 35 支影片與 7.5 週產能

**風險等級**：高
**建議補強**：以「可發布成品」而非生成次數排產，建立每人同等的片數、時長、畫質、發布時段與首頁曝光配額。至少加 20–30% 返工容量與 1 週緩衝；開賽閘門應是 20 位自介全部通過 QA、真人書面核准、R2 素材至少完成 70%，而非到日期就開。決選素材可對階段二的 10 人預做可重用底稿，確定前 5 後再完成；三人成團合演應在結果確定後另留製作期，或明定 W7 的「團體合演」只是五人決選舞台。依此重排後，合理工期較接近前置 3–4 週＋正式賽程 5–6 週。

### 針對 §4 方案丙 —— 實名 ×3 票權加權

**盲點**：實名 ×3 把兩件不同的事混在一起：實名可提高「一人一帳」可信度，但不代表同一自然人的意見應值三倍。若「一般認證」不能證明唯一自然人，分身仍可用多個 ×1 壓過單一 ×3；若能證明唯一自然人，則再乘三沒有防弊必要。這會讓決選被少數實名會員支配，也可能被視為以選秀結果交換個資。原案沒有用目前會員的實名／一般／未認證人數與活躍率回放結果，因此無法知道 ×3 會不會直接改變前三名。

**風險等級**：高

### 針對 §0、§6、§7 —— 5 位真人的肖像、聲音與退出機制

**盲點**：「出借肖像權、臉維持真人樣貌」不足以覆蓋實際工作。AI 素材還會涉及臉部／身形合成、聲音或歌聲、劇情台詞、服裝與身體呈現、廣告代言印象、訓練供應商與跨境處理。真人與純 AI 角色同場若未清楚揭露，會有誤導；若揭露，又會增加肉搜、性騷擾、深偽二創與人身安全風險。現案也沒有真人中途撤回、違約、落選／成團後使用、爭議素材下架和模型／訓練資料刪除機制。台灣法務部函釋亦將肖像視為重要人格法益，營利使用不能只靠概括授權；參考：[法務部肖像權函釋](https://mojlaw.moj.gov.tw/LawContentExShow.aspx?id=FE243425&type=e)。
**風險等級**：高
**建議補強**：素材開工前簽「逐用途」授權與參賽契約，至少涵蓋 AI 合成／改作、聲音與歌聲、身體與服裝邊界、平台／地域／期間、商業與廣告使用、模型供應商及跨境處理、審片／否決範圍、禁止色情與敏感情境、資安、報酬、退出／違約、賽程中斷、期滿下架及資料／模型處置。前台應一致揭露哪些角色為全虛構、哪些為經本人授權的 AI 化真人，但不公開不必要個資；為真人提供快速檢舉、封鎖、蒐證與下架窗口。

### 針對 §1、§7 —— 人設素材、公平曝光與內容權利

**盲點**：15 位 AI 人設的完成度不均：只有 5 位已訓練，影片為 9／4／4／3／1 分布，其餘 10 位尚無影片；再加 5 位真人後，選手起跑線差距更大。網站把身高、三圍、罩杯作為顯著規格，並有部分偏成人情境的既有素材；若直接導入大眾選秀，容易讓活動被理解為身材排行而非才藝選秀，增加平台限流、廣告品牌安全、性騷擾與真人參賽者比較壓力。音樂、編舞、動作參考、歌聲與生成模型輸出權利也未列入清冊；純 AI 生成內容是否具有可主張的著作權，仍取決於人類創意投入，不能假設素材天然可排他授權。參考：[智慧財產局 AI 生成內容說明](https://www.tipo.gov.tw/tw/copyright/692-86740.html)。
**風險等級**：高
**建議補強**：建立曝光公平矩陣，逐人記錄片數、秒數、首頁位置、發布時段、付費推廣與素材品質；投票開始前不得讓個別人因庫存多而多曝光。公開頁把胸圍／罩杯降為非核心或移除，才藝證據與性格鉤子置前；成人暗示素材與選秀主品牌分庫、分權、分發。每支片建立 rights manifest：影像模型與輸入、音樂、編舞／動作來源、聲音、字型、素材、人工創作貢獻、授權範圍及到期日。

### 針對 §0、§3 —— 系統責任、稽核與事故處理

**盲點**：目前分工把營運與系統全交給客戶，卻未定義誰對票數錯誤、Agent 誤發、Portal API 金鑰外洩、排行榜與帳本不一致、候選人素材延遲負責。製作方控制素材品質，客戶控制投票、曝光與結算，兩方都能非直接地影響名次，若沒有獨立證據鏈，任何異常都會被解讀為黑箱。9 支 Agent 是攻擊面，不是「接近零工時」的保證。
**風險等級**：高
**建議補強**：補 RACI 與事故矩陣，逐項指定 owner、SLA、停賽權、回滾、對外說法與賠償邊界。投票服務與發文 Agent 分離權限，採最小權限、金鑰輪替、簽章 webhook、不可變更稽核日誌、每日對帳與異地備份；Agent 不得有改票或改結算權。開賽前聘請未參與內容與論壇營運者做一次規則／帳本稽核，公布總票、無效票原因分類及最終稽核摘要。

### 針對整體 —— 最容易失敗的原因

**盲點**：此類企劃最常見的失敗，不是生成品質單點，而是「只有選秀事件，沒有追星關係」。20 張漂亮臉加才藝短片能帶來第一次點擊，卻未必讓會員記住、偏愛、為角色辯護並在成團後繼續回來。本案已踩到三個前兆：個體敘事被集中帳號稀釋、素材量極不均、成團後內容與商業模式只寫成「常態供應」而無 90 天計畫。若投票又被積分大戶或實名倍率主導，普通會員會迅速認定結果與自己無關。
**風險等級**：高
**建議補強**：在開賽前為每人設計「一句記憶點＋一條 6 週成長弧＋固定互動梗＋一次合作／衝突節點」，每週不只發表演，也要有選擇、失敗、回應粉絲的連續劇情。先定義成功／停損 KPI：合格投票人數、首投→次週留存、每人支持集中度、論壇新增與舊會員回流、實名轉換、無效票率、負面事件率，以及成團後 D30／D90 留存。成團前就完成 90 天內容庫、團體互動設定、商業化邊界與落選者退場／轉常駐腳本。

### 未被規劃到的項目

**盲點**：尚缺以下上線必要項目：① 完整活動辦法與規則版本鎖定；② 年齡／地域資格、獎品稅務與客服；③ 票務威脅模型、壓測、備援、停賽與災難復原；④ 同票、退賽、遞補、素材延遲、平台下架與不可抗力；⑤ AI 揭露、角色言論責任與更正機制（台灣《人工智慧基本法》治理方向已包含 AI 產出內容的適當揭露／標記，參考[數發部說明](https://moda.gov.tw/major-policies/ai/governance/19248)）；⑥ 社群守則、性騷擾／仇恨／國籍攻擊／肉搜與未成年觀眾保護；⑦ 角色名、團名、handle、音樂與素材的商標／權利清查；⑧ 會員個資與投票資料保存期限、供應商跨境與刪除流程；⑨ 積分經濟衝擊模擬（舊戶存量、通膨、輪盤與兌票的排擠）；⑩ 成團後 90 天預算與停損點。
**風險等級**：高
**建議補強**：把上述項目變成「開賽 Gate Checklist」，每項均需 owner、完成證據與 deadline；任何一項高風險 Gate 未完成即不開票。第一季應刻意減法：單一主帳號＋可訂閱人物頁、等值活動票、非排名型輪盤、免費且不可兌現的預測、可稽核帳本、等量曝光；待完成一季真實數據後，再測試積分兌票與更複雜玩法。
