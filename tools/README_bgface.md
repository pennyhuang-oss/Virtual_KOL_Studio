# `bgface_screen.py` — 背景撞臉篩檢（半成品，已知限制）

**用途**：把「我有沒有剛好去看那一區」變成一道自動篩檢。
偵測畫面裡所有的臉 → 最大的當主體 → 其餘每張臉算與該人設 `identity_master.jpg` 的身分距離。

```
python3 tools/bgface_screen.py kols/<pid>/identity/identity_master.jpg  img1.png img2.png ...
```

距離基準沿用 2026-09 碰撞測試：同人不同張 ≈ 0.0129 · 不同人 master 互比 ≈ 0.0157 · 當時碰撞門檻 0.0220。
背景臉距離 **< 0.0157 = 撞臉**。

## 實測狀態（2026-09-09）

| | 結果 |
|---|---|
| rin D4（目視 3-4 張背景臉都撞臉） | ✅ **抓到**：偵測 2 張臉，背景距離 0.0047 → 標記撞臉 |
| rin D2（目視至少 2 張背景臉撞臉） | ❌ **漏掉**：整張圖只偵測到 1 張臉 |

**原因**：小而模糊的背景臉在 1536px 的整張圖裡太小，mediapipe 抓不到。

**已嘗試但失敗的修法**：把畫面切成重疊分塊、各自放大 2.5x 再偵測。
分塊確實能在 rin D2 的背景區抓到臉，但合併去重的邏輯有 bug
（去重半徑用了偵測到的臉寬，遇到一張異常大的誤偵測就會把真的臉一起吃掉），
導致合併後反而只剩 1 張，甚至把背景臉當成主體。**bug 已定位，尚未修好。**

## ⚠️ 最重要的一條使用限制

即使修好合併邏輯，抽查顯示 mediapipe 在這類畫面上大約只能找到
**目視可見臉數的一半**。所以這支程式：

- **可以用來抓陽性** —— 它說撞臉，就是撞臉，直接重跑那一格
- **不能用來證明沒有撞臉** —— 它報 0 不代表乾淨，仍必須人工複看背景區

不要把它的 0 當成通過。
